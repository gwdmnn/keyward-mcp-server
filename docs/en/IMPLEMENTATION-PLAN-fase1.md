# Implementation Plan — db-mcp-server (Phase 1)

Companion to [FDD-db-mcp-server.md](./FDD-db-mcp-server.md) (v0.1.0).
Date: 2026-08-14 · Owner: Guilherme Weidmann

Goal of this phase: deliver a local, passphrase-based MCP server that keeps credentials out of the model's transcript, with read-only reads by default, confirmed writes, and migration of the existing config into a catalog + vault.

---

## 1. Stack and dependencies

| Item | Choice | Reason |
|---|---|---|
| Language | Python ≥ 3.11 | `mcp` SDK, `pywin32`-free (DPAPI not used in this phase), psycopg/sshtunnel ecosystem |
| MCP server | `mcp` (FastMCP) | `@mcp.tool()` + structured output via Pydantic; `mcp.run()` defaults to stdio |
| PG driver | `psycopg[binary]` ≥ 3.1 | native `conn.read_only`, parameter binding, timeouts |
| SSH tunnel | `sshtunnel` ≥ 0.4 | in-process tunnel, `local_bind_address=('127.0.0.1', 0)` (ephemeral port) |
| Crypto | `cryptography` ≥ 42 | `Scrypt` (KDF) + `AESGCM` (authenticated encryption) |
| Config | `PyYAML` ≥ 6 | `registry.yaml` |
| Validation | `pydantic` ≥ 2 | tool input/output schemas |
| Tests | `pytest`, `pytest-mock` | unit; optional integration with Postgres in a container |

Manager: `uv` (or `pip` + venv). Publish as an installable package (`db_mcp_server`) with two console entry points: `db-mcp-server` (server) and `db-vault` (admin CLI).

## 3. Milestone sequence (implementation order)

The order is bottom-up: each layer is testable in isolation before being plugged into the server. **M1→M4 have no network dependency** (they can be completed and tested without touching a DB/tunnel).

### M0 — Project scaffold
- `pyproject.toml` with deps and entry points; `src/` layout; `.gitignore`; skeleton `README`.
- **Acceptance:** `uv sync` installs; `db-mcp-server --help` and `db-vault --help` respond (even as stubs).

### M1 — Crypto core (`crypto.py`)
- `derive_key(passphrase, salt, n, r, p) -> bytes` (scrypt, 32 bytes).
- `encrypt(plaintext: bytes, key) -> EnvelopeHeader+ciphertext` with a **fresh random nonce** (12 bytes) each call.
- `decrypt(envelope, key) -> bytes` (GCM tag failure = clear exception).
- `atomic_write(path, data)` (tmp + `os.replace`).
- **Acceptance (test_crypto):** encrypt→decrypt round-trip; wrong passphrase raises; two `encrypt`s of the same text produce different nonces/ciphertexts; tampering with the ciphertext fails verification.

### M2 — Vault (`vault.py`)
- `Vault.open(path, passphrase) -> Vault`: reads the envelope, derives the key, decrypts → `dict[str, {user,password}]` in memory. Error → `VAULT_LOCKED`.
- `Vault.get(secret_ref) -> Credential` (error → `SECRET_NOT_FOUND`).
- `Vault.set/remove/keys()` (used only by the CLI; not exposed to the server).
- `Vault.save(path)` re-encrypts and writes atomically.
- **Acceptance (test_vault):** open with right/wrong passphrase; get of an existing/absent ref; set→save→reopen persists; `keys()` never exposes values.

### M3 — Catalog (`catalog.py` + `models.py`)
- `Catalog.load(path) -> Catalog` (YAML parse + Pydantic validation; defaults applied).
- `Catalog.resolve(customer, env, service) -> Resolved{tunnel_profile, dbname, secret_ref, max_rows, statement_timeout_ms}` (error → `CATALOG_NOT_FOUND`).
- `Catalog.list_databases() -> Catalog(view with no secrets)` for the tool of the same name.
- `Catalog.tunnel_key(customer, env) -> (customer, env)`.
- **Acceptance (test_catalog):** resolve of a valid target; `CATALOG_NOT_FOUND` for unknown customer/env/service; `list_databases` contains no `secret_ref`, jump host, or PEM.

### M4 — Admin CLI (`vault_admin.py`) — Contract 7
- Subcommands `set <ref>` (getpass for the password), `rm <ref>`, `list`, `verify` (cross-checks `registry.yaml` × vault).
- Passphrase from `DB_MCP_PASSPHRASE` or a prompt (`getpass`). Password **never** via argv.
- **Acceptance:** `set` writes and is read back by `Vault.open`; `list` shows keys only; `verify` reports `missing_in_vault`/`orphan_in_vault`; the password does not appear in `ps`/history (read via getpass).

### M5 — Tunnel manager (`tunnel_manager.py`)
- `TunnelManager.get(tunnel_profile) -> (host, port)`: reuses an active tunnel per `(customer, env)`, otherwise opens `SSHTunnelForwarder` with `ssh_pkey=keys/<pem>`, `remote_bind_address=(db_host, db_port)`, `local_bind_address=('127.0.0.1', 0)`; returns `local_bind_port`.
- Idle-timeout (thread/timer) and `close_all()` on shutdown. Handshake error → `TUNNEL_FAILED`.
- **Acceptance (test_tunnel_manager, with mocked SSH):** reuse does not open a 2nd tunnel for the same key; a connection failure becomes `TUNNEL_FAILED`; `close_all` shuts everything down. *(A real test against a jump host stays a manual verification — see §5.)*

### M6 — Query executor (`executor.py`)
- `run_read(resolved, creds, sql, max_rows) -> QueryResult`: `psycopg.connect` to `127.0.0.1:<port>/dbname`, `conn.read_only = True`, `statement_timeout`, runs, applies `max_rows`, sets `truncated`.
- `run_write(resolved, creds, sql, confirm) -> WriteResult`: requires `confirm`; read-write transaction; `COMMIT`/`ROLLBACK`; returns `affected_rows`.
- Map psycopg exceptions → `QUERY_READONLY_VIOLATION` / `QUERY_TIMEOUT` / `DB_ERROR` (message without credentials).
- **Acceptance (test_executor_readonly, Postgres container):** SELECT returns rows; INSERT in `run_read` → `QUERY_READONLY_VIOLATION`; `max_rows` truncates with the flag; `run_write(confirm=false)` → `WRITE_NOT_CONFIRMED` with no effect; `run_write(confirm=true)` commits.

### M7 — MCP server (`server.py`)
- `FastMCP("db")` with the typed tools: `list_databases()`, `run_query(...)`, `run_write_query(...)` returning the Pydantic models (structured output).
- Startup: load config → `Vault.open` (failure = server does not start) → `Catalog.load` → `Catalog.verify_against(vault)` (warning on missing refs) → instantiate `TunnelManager`. Shutdown: `close_all()`.
- Domain errors → structured `{error_code, message}` return (never leaks a credential/stacktrace with a secret).
- `mcp.run()` (stdio).
- **Acceptance:** with a test MCP client (or `mcp dev`), `list_databases` responds with no secrets; `run_query` runs end-to-end against a real target (manual verification §5).

### M8 — Bootstrap importer (`bootstrap.py`)
- Reads a single `bootstrap.yaml` (`registry.yaml` shape + `user`/`password` per service) and splits it into `registry.yaml` (no credentials) and the vault (sealed secrets). `secret_ref` derived as `customer/env/service`. Input validated by Pydantic; `bootstrap.yaml` is git-ignored (template: `bootstrap.example.yaml`).
- `--dry-run` shows the summary without writing; `--force` to overwrite an existing `vault.enc`. Never prints credential values.
- **Acceptance (test_bootstrap):** the split derives the `secret_ref`s, the generated `registry.yaml` contains no credentials and validates through `Catalog`; `--dry-run` writes nothing; malformed input is rejected; a full run produces a readable vault and refuses to clobber without `--force`.

### M9 — Integration, docs, and cutover
- `README`: install, `bootstrap`, `db-vault verify`, register with Claude Code (the `mcpServers` block from FDD §5, Contract 6), remove credentials from the `.env` files.
- Update/deprecate the `database-connection` skill to point at the MCP server (or remove it from the flow).
- **Acceptance:** the cutover runbook executed on a real workload (§5) and plaintext credentials removed from the working tree.

## 4. Signature specifications (internal contracts)

```python
# models.py
class Credential(BaseModel): user: str; password: SecretStr
class TunnelProfile(BaseModel): jump_host: str; jump_port: int; jump_user: str; pem_key: str; db_host: str; db_port: int
class Resolved(BaseModel): tunnel_profile: TunnelProfile; tunnel_key: tuple[str, str]; dbname: str; secret_ref: str; max_rows: int; statement_timeout_ms: int
class QueryResult(BaseModel): columns: list[str]; rows: list[list]; row_count: int; truncated: bool
class WriteResult(BaseModel): affected_rows: int; committed: bool
class ErrorResult(BaseModel): error_code: str; message: str

# crypto.py
def derive_key(passphrase: str, salt: bytes, n: int, r: int, p: int) -> bytes
def encrypt(plaintext: bytes, key: bytes) -> dict            # envelope header + ciphertext_b64
def decrypt(envelope: dict, key: bytes) -> bytes
def atomic_write(path: Path, data: bytes) -> None

# vault.py
class Vault:
    @classmethod
    def open(cls, path: Path, passphrase: str) -> "Vault"    # raise DbMcpError(VAULT_LOCKED)
    def get(self, secret_ref: str) -> Credential             # raise DbMcpError(SECRET_NOT_FOUND)
    def set(self, secret_ref: str, cred: Credential) -> None
    def remove(self, secret_ref: str) -> None
    def keys(self) -> list[str]
    def save(self, path: Path, passphrase: str) -> None

# catalog.py
class Catalog:
    @classmethod
    def load(cls, path: Path) -> "Catalog"
    def resolve(self, customer: str, environment: str, service: str) -> Resolved   # raise CATALOG_NOT_FOUND
    def list_databases(self) -> dict                          # no secrets
    def verify_against(self, vault: Vault) -> VerifyReport

# tunnel_manager.py
class TunnelManager:
    def __init__(self, keys_dir: Path, idle_timeout_s: int)
    def get(self, tunnel_key: tuple[str, str], profile: TunnelProfile) -> tuple[str, int]  # raise TUNNEL_FAILED
    def close_all(self) -> None

# executor.py
def run_read(resolved: Resolved, cred: Credential, local: tuple[str,int], sql: str, max_rows: int) -> QueryResult
def run_write(resolved: Resolved, cred: Credential, local: tuple[str,int], sql: str, confirm: bool) -> WriteResult
```

## 5. Test strategy

**Unit (no network) — covers M1–M4, M8:**
- `crypto`: round-trip, unique nonce, tamper detected, wrong passphrase.
- `vault`: set→save→reopen persistence, `keys()` without values.
- `catalog`: resolve/errors, `list_databases` without secrets.
- `bootstrap`: `bootstrap.yaml` fixtures → expected registry/vault; `--dry-run` inert.

**Integration (Postgres in a container) — covers M6:**
- SELECT ok; INSERT via `run_read` → `QUERY_READONLY_VIOLATION`; `max_rows`/`truncated`; `run_write` confirm true/false; `statement_timeout` → `QUERY_TIMEOUT`.

**Tunnel (M5):** SSH mocked in tests; **manual verification** against a real jump host before cutover.

**End-to-end (M7/M9):** run the server via `mcp dev` (or a test client), `list_databases` → `run_query` against a real environment, checking that **no credential** appears in the tools' I/O.

## 6. Security checklist (phase completion gate)

- [ ] `.gitignore` blocks `vault.enc`, `keys/*`, `*.env`; nothing secret in the versioned working tree.
- [ ] No MCP tool accepts or returns `user`/`password`/DSN/PEM (review of the Pydantic schemas).
- [ ] Passphrase only via `DB_MCP_PASSPHRASE`/prompt; never in `registry.yaml`, argv, or logs.
- [ ] `vault_admin`'s password read via `getpass` (not in argv/history).
- [ ] Fresh AES-GCM nonce on every write; atomic vault write.
- [ ] Error messages (`DB_ERROR` etc.) do not echo credentials or the full DSN.
- [ ] Plaintext credentials removed from the `.env` files after cutover.
- [ ] (Optional, recorded in the FDD as Phase 2) Claude Code denylist for `vault.enc`/`keys`/`psql`/`docker`.

## 7. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Lost passphrase ⇒ unrecoverable vault | Document in the README; keep a vault backup + store the passphrase in a personal manager; refs recreatable via `bootstrap` from the source data while it still exists. |
| Corrupting `vault.enc` on write | Atomic write (tmp+replace) + backup before `set/rm`. |
| Port collision / tunnel leak | Ephemeral ports (`127.0.0.1:0`) + `close_all` on shutdown + idle-timeout. |
| Bypass via Claude's shell (same host) | Acknowledged in the FDD; hardening (denylist) deferred to Phase 2 — a conscious decision. |
| Divergent schema across services (bootstrap) | `--dry-run` + explicit per-service input; report of unmapped items. |

---

## 8. Recommended execution order

`M0 → M1 → M2 → M3 → M4` (all offline, already delivers a usable vault CLI) → `M8` (bootstrap, populates real data) → `M5 → M6` (network/DB) → `M7` (server) → `M9` (cutover). Each milestone lands with its acceptance tests green before the next.
